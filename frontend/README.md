# FraudMesh investigator dashboard

Dependency-free HTML/CSS/JavaScript, continued from the team's integrated frontend. The repository-root `docs/data_contract.md` is authoritative. Backend, ML, graph and privacy implementations are unchanged by this frontend work.

## Run the integrated application

From your repository root, install the root requirements in your Python environment, then:

```sh
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Open http://127.0.0.1:8000. The dashboard detects the unified service and loads computed synthetic results. Choose Shared team scenario, Cross-bank ring, Normal activity or Local positive control, then Run analysis. The configurable API URL is in the gear dialog.

## Offline frontend demonstration

Node.js 18 or newer; no npm installation or build:

```sh
cd frontend
node server.mjs
```

Open http://localhost:4173. The initial six-event fixture is explicitly authored. Use play, pause, reset or step for illustrative replay. To show actual computed output without a running API, select a scenario and click **Load saved computed example**. The badge says **Saved computed · synthetic**, and replay is disabled. Normal activity is a negative control; Local positive control includes a local structure. JSON exports retain saved-result provenance without claiming measured replay timing.

Windows users may double-click START-DASHBOARD.cmd. Its optional Codex-runtime fallback is machine-specific; the commands above are portable. Python's `python -m http.server 4173 --bind 127.0.0.1` also serves this directory. Direct file opening is unsupported.

## What this branch adds to the integrated dashboard

- Actual API request validation before forwarding permitted signals; no raw rows, linkage keys, nested scalar values or unexpected request fields.
- Cancellable requests, timeouts, clear progress and failures, and protection against a late API response replacing a manually selected fallback.
- Saved common/ring/normal/local outputs generated by the unchanged authoritative service, with backend commit and source hashes.
- Highlighted supporting evidence rows, contributing institutions and per-signal scores.
- Explicit shared-entity memberships; neutral multi-institution graph symbols and decimal, uncalibrated incident scores.
- Separate transaction flags, local structures, combined structures and multi-bank case counts, without a shared accuracy bar.
- Backend analysis timing with its actual scope, excluding local ML, HTTP and rendering. Missing timing stays unavailable; saved examples do not fabricate measurements.

Node score aggregation is the authoritative maximum incident signal score, not a fraud probability. Local views retain the team's institution-specific projections. The browser receives the permitted analysis response, so view controls are not bank authentication. Confidential-execution flags are backend claims; no frontend attestation or privacy certification is provided.

## Verify

```sh
node --test frontend/tests/*.test.mjs
node --check frontend/src/app.js
```

Run these from the repository root. The backend response tests require Python with root requirements installed. Set FRAUDMESH_TEST_PYTHON to your environment's Python executable if needed. The original model tests also work standalone: `node --test frontend/tests/model.test.mjs`.

Regenerate saved outputs from unchanged local backend code: `python frontend/scripts/generate-snapshots.py`. No raw ledger or secret is serialized. No inference latency is recorded by the generator.

See docs/recovery-verification.md for executed checks, docs/data_contract.md for frontend boundary details and docs/demo_script.md for the demo. The older tests/mock-api.mjs helper predates the authoritative contract; use the real integrated API for current endpoint verification.
