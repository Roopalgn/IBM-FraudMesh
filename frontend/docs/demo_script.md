# Person 4: Demo and presentation handoff

## Two-minute live sequence

1. Open the dashboard. Say: “These are synthetic entities and pre-authored outcomes. Our experiment is whether connecting permitted relationships reveals a pattern that each bank's local view cannot reconstruct.”
2. Select **Local only**, then **Reset** and **Play scenario**. Three local fragments appear, with zero collaborative cases. Pause if needed. Select each bank card to show its local finding. The UI is illustrating institutional visibility, not enforcing bank authorization.
3. After event six, select **Collaborative**. Six relationships connect the six pseudonymous entities across three banks. One review case appears. Say: “The final relationship closes the cycle. This case has evidence that no one bank's fragment contains.”
4. Select an entity in the graph to inspect its local risk. Choose **Evidence** to show relationship IDs, paths, coarse time buckets and risk bands. The side panel explains the cross-institution path, closed cycle and propagation pattern.
5. Open **Data boundary**. Show retained-local fields and shared relationship fields. Say: “This fixture has zero raw transaction rows. Pseudonyms and relationship signals are still sensitive. Confidential execution is a deployment capability our infrastructure teammate must verify; this frontend does not claim it is already implemented.”
6. Open **Replay trail**. Explain that it is the presentation's scenario trace, not a tamper-evident system audit log. **Export case** downloads the visible case with source and limitation labels.

## Thirty-second story

“One bank sees an unfamiliar relationship. Three banks can reveal a coordinated network. FraudMesh keeps raw banking records at their institutions and connects a defined set of pseudonymous signals. In this controlled synthetic case, local analysis shows disconnected fragments; the shared graph reveals a six-entity cycle with explicit evidence. Our dashboard makes both the collaboration benefit and the sharing boundary visible.”

## With the integrated backend

Use the gear icon to set the lead's API URL. A successful connection changes the source label and disables synthetic replay. If integration is unavailable, restore **Use synthetic demo** and explicitly identify it as the fallback. Do not claim the fixture proves detector performance or a LinuxONE deployment. The contract harness only tests HTTP wiring.

## Recording / rehearsal checklist

- Keep the fixture as the deterministic backup; no external asset or dataset access is needed.
- Start local, finish collaborative, and show why the final relationship changes the result.
- Distinguish a local flag, a collaborative case and a confirmed fraud verdict.
- Show the privacy limits panel, rather than saying “perfect privacy” or “zero data movement.”
- Ask the ML teammate for measured evaluation and the lead for actual LinuxONE/security status before adding those claims to the final pitch.
- Capture a short screen recording during the team's rehearsal; no video has been generated by this frontend deliverable.
